# 巧未来-波龙量化 · 系统用户体验走查与整改报告

版本：v1.5 · 日期：2026-11-20 · 视角：首次使用的真实用户（不做开发假设）

---

## 一、先回答三个核心疑问

### 1. 十个选股策略为什么只有一个执行按钮？统一用那个吗？

**原设计确实是这样**：10 张卡片相当于「单选按钮」，点卡片只改变 `selectedSelector`，真正执行时统一由下方「执行全市场选股」按钮把该变量提交给 `/api/select`。所以按钮背后是同一套引擎 + 可插拔策略，功能上没有缺失，但**界面没有讲清这一点**，用户自然会怀疑"是不是只有多因子在生效"。

**本轮整改**：
- 每张卡片新增独立入口「▶ 用此策略选股」，点它 = 选中该策略 + 立即执行。
- 统一按钮文字改为动态：`▶ 执行【价值选股 · 低估值】选股`，当前策略不再是藏在页面顶部的角标。
- 页面顶部明确写出"10 张卡片为单选"的操作说明。
- 「全链路 → 选股一条龙」的策略下拉框与选股页**双向同步**，不会再出现"选股页选了成长、一条龙却跑价值"的静默错配。

### 2. 工作流程是怎么设计的？

系统有**两条互补管线**，不是一条：

| 管线 | 页面入口 | 回答的问题 | 步骤 |
|---|---|---|---|
| TeamPipeline（单标的全链路） | 全链路工作流 → 启动全链路 | 某个标的 + 某个交易策略，能不能跑通团队流程 | 数据 → 统一口径 → 策略 → 稳健检验 → 回测 → 策略守护 → 风控 → 合规 → 执行路由 → AI 复盘（11 步 SSE） |
| SelectionPipeline（选股一条龙） | 全链路工作流 → 选股一条龙 / 选股结果 → 送入一条龙 | 买哪些、怎么配、能不能下单 | 选股 → 组合回测 → 折外稳健 → 风控 → 合规 → 实盘意图 → AI 复盘（8 步 SSE） |

**关键边界**：两条管线都只生成 `VALIDATED_ONLY` 委托意图，**绝不真实报单**。真实报单只能通过 `scripts/verify_qmt_paper.py` 在券商模拟账号上显式执行，本机当前不具备前置条件。

### 3. 策略库里的 13 个策略怎么用、用在哪里？

「策略库」是**交易择时策略**（回答"何时买卖"），不是选股策略。它们被用在 5 个地方：

1. 回测中心 → 单标的回测（下拉框）
2. 回测中心 → K 段折外稳健性检验
3. 回测中心 → 多策略对比（默认前 8 个，各用默认参数以保证公平）
4. 回测中心 → 多标的组合回测的「策略择时」信号模式
5. 回测中心 → 参数自动寻优；全链路工作流 → 启动全链路的策略输入

**走查发现的真问题**：页面上有参数输入框，`collectParams()` 函数也存在，但**从未被调用**——用户调的参数根本没进回测。本轮已修复：策略库选中项与 4 个页面的下拉框同步，参数真实传入回测/稳健性/全链路；寻优结果可一键回写到参数面板。

与「全市场选股」10 个策略（回答"买什么"）的关系：后者只做全市场截面打分，产出的股票池/权重通过「送入一条龙」进入组合回测与风控，形成闭环。

| 2 | 全市场选股/全链路 | 两处选股策略选择器互不同步；一条龙默认跑 multi_factor | 用户以为在跑"价值选股"，实际跑另一策略 | 高 | 已修复 |

## 三、本轮改动的文件

- `web/index.html`：两套策略说明、选股卡片执行入口、动态按钮、送入一条龙、K 线复位、模式/健康状态容器、AI 配置说明。
- `web/app.js`：策略下拉框与参数同步、参数真实传参、选股策略同步、结果复用、按钮/超时/错误反馈、模式标签、数据源状态、结果刷新、寻优参数回写。
- `web/config.js`：切页缓存、脱敏值保护、模式标签复用。
- `web/server.py`：稳健性接口接参数、一条龙接 `selection` 复用、配置保存拦截脱敏密钥。
- `core/workflow/selection_pipeline.py`：`preset_selection` 支持，复用已选结果跳过全市场扫描。
- `start.bat`：Windows 一键启动。
- `README.md`：v1.5 变更说明与启动方式。

## 四、实测验证（真实数据）

- Python 编译、JS 语法检查全部通过；静态核对 102 个 HTML id 与 89 处 JS 引用，无缺失。
- 受控启动服务（8766 端口，测试后已关闭）：策略 13 个 / 选股策略 10 个；自定义参数 `dual_ma(fast=7,slow=25)` 稳健性检验返回 score -0.0568 / 5 段，证明参数已生效；选股与一条龙接口均正常启动。
- 复用真实选股结果（value 策略 5 只：002958.SZ、002582.SZ、603323.SH、601169.SH、601577.SH）跑一条龙：输出"复用已选股结果 5 只（不再重新扫描全市场）"，组合收益 55.90%、回撤 -30.72%、夏普 0.328，生成 5 笔 VALIDATED_ONLY 意图，耗时 18.3 秒。

## 五、仍需用户环境配合 / 已知边界

1. **券商模拟账号报单**：本机无 xtquant、无 miniQMT 进程、无 QMT 路径与账户 ID，无法真跑。脚本与前置条件已就绪（`scripts/verify_qmt_paper.py`、`reports/qmt_paper_verify.json`）。
2. **AI 自然语言分析**：需在「系统配置 → AI 接口」填 Key 才启用云端；未配置时本地工具直答可用。
3. **全市场选股耗时**：首次扫描约 5500 只真实标的需 30~40 秒，界面已有进度条与 SSE 日志；快照拉取阶段每 10 页回报一次，不再长时间静默。需历史 K 线的策略受「历史精算池」上限影响（默认 60 只，最终仅从该真实精算池中选股），参数区已改为按策略动态显示。
4. **图表交互**：按用户要求实现方向键缩放/平移；鼠标滚轮缩放与拖拽平移暂未实现。
5. **多用户并发**：寻优与一条龙结果存于服务端全局变量，单用户本地终端场景无碍；多人同时使用会互相覆盖结果。
