一、系统定位与核心原则

1.1 它解决什么问题

传统量化工具常见三个短板：数据口径不统一、回测偷偷用随机数或未来函数、连接失败静默切换成模拟数据却让你以为是真实结果。本系统从设计上堵住这三点，并把「研究 → 回测 → 风控 → 合规 → 执行意图」串成可观测的一条链。

你能做的事在哪个页面数据来源
看真实 K 线、成交量、均线、F10 基本面实时行情东财/腾讯/新浪真实行情
从全市场 5500+ 只股票按 10 种角度选股全市场选股真实快照 + 真实历史 K 线
用 13 个经典策略回测单只股票、看净值/回撤/交易流水回测中心真实前复权日 K + 真实费用
多策略对比、多标的组合回测、参数自动寻优回测中心同上
选股 → 组合 → 风控 → 合规 → 实盘意图一键跑通全链路工作流真实数据，SSE 实时观测
期货/期权/ETF 行情、成本测算、多品种回测多市场品种东财真实合约数据
用自然语言查询数据、编排回测、复盘AI 助手云端 API（可选）+ 真实工具

1.2 五条不可动摇的核心原则

  1. 一律真实数据：任何数据源失败都明确抛错或降级到标注了来源的缓存，绝不伪造价格、绝不用随机数喂回测。
  2. 防未来函数：信号在 T 日收盘产生、成交在 T+1 开盘，回测与实盘共用同一套引擎（core/research/engine.py）。
  3. 稳健优先于漂亮：参数不在样本内取最优，用 K 段折外稳健分 0.6×中位数 + 0.4×最差段 抑制过拟合。
  4. 实盘边界严格：默认 paper/validate 模式只校验不报单；只有显式切到 live 且配齐 QMT 才可能真实下单。
  5. 结果可追溯：每只入选股记录各因子原始值与打分明细，回测含完整交易流水，合规有 append-only 审计日志。
谁适合用：想验证策略想法、做真实数据研究和模拟盘演练的个人与团队。谁不适合：期待「输入资金自动赚钱」的人——本系统不做 AI 荐股、不承诺收益，期货/期权/港股实盘亦未完全接通（见第八章）。

二、安装与启动

2.1 环境要求

项目要求说明

2.2 Windows 一键启动（推荐）

下载/解压项目到本地目录，例如 D:\qiaoweilai-bowlong-quant。路径尽量不要有中文和空格以免个别脚本出问题。
进入项目根目录，双击 start.bat。脚本会自动探测可用 Python：优先 WorkBuddy 内置解释器，其次常见安装路径，最后跳过微软商店的 WindowsApps\python.exe 占位符。
看到命令行显示 Starting server ... Open http://127.0.0.1:8765 即成功；脚本不会自动关窗口，关闭该窗口即停止服务。
浏览器打开 http://127.0.0.1:8765，看到终端界面即启动成功。
这些提示都是正常的，不是失败：① 出现 [OK] The terminal is already running and healthy. 并自动打开浏览器——说明服务已在运行，无需重复启动。② 端口 8765 被占用时脚本会先做健康检查，健康就直接开浏览器，被别的程序占用才提示停掉它或修改 web/server.py 里的端口。

2.3 命令行启动（任意系统 / 调试用）

# 在项目根目录执行
python web/server.py
# 然后浏览器打开 http://127.0.0.1:8765

# 若系统 python 指向微软商店占位符会闪退，请写全路径，例如：
C:\Users\Administrator\.workbuddy\binaries\python\versions\3.13.12\python.exe web\server.py

# 判断服务是否起来（返回 JSON 即成功）
curl http://127.0.0.1:8765/api/status
最常见的启动失败：命令行直接敲 python web/server.py 时窗口一闪而过——多半是 python 命中了微软商店的占位程序。解决：改用 start.bat，或写出真实 Python 的完整路径。

2.4 停止服务与端口

直接关闭运行服务的命令行窗口（或在窗口内按 Ctrl+C）即可停止。默认端口 8765，如需修改，改 web/server.py 中的端口并同步修改 start.bat 里的健康检查地址与浏览器地址。启动脚本已内置「端口占用→健康检查」逻辑，重复双击不会重复起服务。

三、首次配置引导

首次打开时若配置未完成，会弹出「欢迎使用」引导浮层，列出待办项。可以点「跳过」先用起来——所有功能在不配置 AI 的情况下也能运行（AI 助手会降级为本地工具直答）。

3.1 配置中心在哪、怎么改

左侧最下方「系统配置」进入。它是 schema 驱动的动态表单，共 9 个分组；改完点「保存并生效」，即时热更新、无需重启服务。密钥类字段界面脱敏显示（如 sk-****def），可点「显示」切换明文。切换分组前会自动缓存当前页未保存的修改，不会静默丢失。

分组关键项为什么重要
系统mode：backtest / paper / live；端口、主题、日志级别运行模式总开关，切 live 会弹二次风险确认
AI 接口provider、api_key、base_url、model、temperature、enable_tools填完点「测试连接」验证，再保存
数据源主源(eastmoney/tencent/sina)、缓存 TTL、复权方式、脏数据校验默认东财，失败自动降级到腾讯/新浪
回测初始资金(默认100万)、滑点、佣金、基准、折数直接影响所有回测的绩效数字
风控单票仓位上限、总仓位、回撤熔断、日内亏损熔断、ST 过滤控制风险敞口
合规单笔金额/日内次数上限、交易时段、审计留痕、禁投池机构级合规闸
执行broker(qmt/ctp/hk/validate)、QMT 路径、账户ID、二次确认实盘才需要；默认 validate 不报单
选股默认选股数、历史精算池、最小成交额、各因子权重(兼容旧版)各策略的实际阈值在「全市场选股」页动态设置
通知渠道(none/webhook/email)、熔断/退役告警需要时才配

3.2 接入云端 AI（可选但推荐）

进入「系统配置 → 🤖 AI 接口」。
选择服务商（DeepSeek / 通义 / 智谱 / Moonshot / OpenAI / Ollama / 自定义），填入 API Key、Base URL、模型名。
点击 API Key 输入框下方的「测试连接」，看到「✓ 连接成功」再点「保存并生效」。

也可用环境变量覆盖（优先级高于界面，适合容器化）：

set QIAO_AI__API_KEY=你的密钥
set QIAO_AI__BASE_URL=https://api.deepseek.com/v1
set QIAO_AI__MODEL=deepseek-chat
环境变量命名规则：前缀 QIAO_ + 分组大写 + 双下划线 + 键大写，例如 QIAO_BACKTEST__INITIAL_CASH。未配置 AI 时，助手自动降级为本地工具直答，功能不中断，只是没有自然语言理解能力。

3.3 运行模式怎么选

  • backtest（回测）：只做历史回测与研究，不涉及任何实盘概念。新手建议从此开始。
  • paper（模拟/校验，默认）：系统默认模式。全链路与一条龙只生成 VALIDATED_ONLY 委托意图，绝不真实报单。
  • live（实盘）：切到该模式会弹窗二次确认并校验 QMT 路径/账户；顶部徽章变红警示。没有券商权限和充分模拟验证前不要切换。

五、逐页使用指南（重点）

5.1 总览仪表盘

  • 数据源健康监控：实时探测东财/腾讯/新浪三源是否在线，显示在线数。若某源离线会自动走备源，这里能看到状态。
  • 结果回报中心：显示最近一次运行的绩效与净值曲线，结果落盘持久化（reports/last_result.json），刷新页面或重启服务都不丢失；有「刷新结果」按钮从服务端重载。
  • 系统能力矩阵：列出版块与版本信息。
  • 实时运行窗口：底部 LIVE STREAM 区域滚动显示各长任务的进度与日志，任何耗时操作都在这里同步反馈。

5.2 实时行情（K 线 / 成交量 / 均线 / F10）

在「股票代码」输入框键入代码（如 600519，支持 6 位纯代码或 600519.SH），点「查询行情」；也可点快捷按钮五粮液/中国平安/宁德时代。
上方四张小卡片显示现价、涨跌幅、成交量、成交额等实时快照。
「真实K线」区默认日 K，可切换 日K / 周K / 月K / 60分 / 30分 / 5分 六种周期；图上是蜡烛图 + 下方成交量副图。
「均线」处有三个输入框 MA1/MA2/MA3（默认 5/10/20，范围 2–120），输入数字即时重绘，颜色分别为橙/紫/青。
光标不在输入框时，按键盘 ← → 左右平移 K 线，↑ ↓ 缩放显示根数；点「复位视图」一键回到最新 60 根。后端返回最近 1000 根真实 K 线以保证平移空间。
下方「F10 基本信息」自动加载公司概况（约 40 字段）与 PE/PB/市值/换手率估值——查询行情后无需额外操作。
涨跌颜色遵循 A 股习惯：红涨绿跌。ETF（如 510300）也能查 K 线，但东财不提供 ETF 的 F10 公司概况，F10 区会显示「-」——这是真实数据边界，不是故障。若 K 线或 F10 显示「加载失败」，多为数据源临时限流，等待几秒刷新即可，系统已内置重试与三源降级。

5.3 多市场品种（期货 / 期权 / ETF）

「品种类别」下拉选择：期货主连（上期所/大商所/郑商所/中金所）、ETF 场内基金、ETF 期权（上交所）。
在「合约」列表中点击选择具体合约，右侧「实时快照」自动加载真实行情。
「成本测算」输入价格与数量点「测算」：期货按保证金×乘数 + 按手手续费（T+0 双向），期权按权利金×乘数 + 按张手续费（T+0 双向），ETF 免印花税（T+1）。
「真实K线 + 多品种回测」设快线/慢线（默认 5/20），点「运行回测」跑均线交叉策略，含真实 K 线与防未来函数。
实盘执行默认校验模式，不产生真实委托。期权单合约历史受生命周期限制（往往只有几个月），长周期回测会受限——这是真实边界。

5.4 策略库（13 个交易择时策略）

这里回答「何时买卖」。13 个策略：双均线、MACD、海龟通道突破、Dual Thrust 区间突破、ATR 通道、布林带均值回归、RSI、KDJ、N 日动量、双动量轮动、多因子(RPS)、配对交易、网格交易。全部按公开经典原理自研实现，无 GPL 许可风险。

点击策略卡片选中，下方「参数调节」区自动显示该策略的可调参数（如双均线的快/慢线天数）。
调整参数后，这些值会自动带入「回测中心」单标的回测、稳健性检验、组合回测择时信号、全链路工作流；多策略对比则用各策略默认参数以保证公平。
参数不在样本内取最优——系统用 K 段折外稳健分抑制过拟合；寻优结果可一键回写到本页参数面板。

为什么要「历史精算池」？需要历史数据的策略（动量/反转/低波等）只对快照靠前的若干只票拉真实日 K 精算，避免对 5000+ 只全部拉历史导致过慢；最终只从真实算过历史的池子里选股。所以调大这个值会更慢但覆盖更全。数据不足时结果会明确标注警告，不伪造。

5.6 回测中心

① 单策略回测

输入代码、选策略，点「运行回测」→ 绩效八宫格（总收益/年化/最大回撤/夏普/胜率/交易次数等）、净值曲线、最近 40 笔交易流水。点「稳健性检验」→ K 段折外稳健性结果。

② 多策略对比分析

输入对比标的，点「运行多策略对比」→ 默认前 8 个策略并列回测，按夏普比率排序，看哪个策略在同一标的上更合适。

③ 多标的组合回测

填逗号分隔的多个代码、选策略、信号模式（策略择时 / 选股权重持有）、再平衡周期（日/周/月/不调仓），点「运行组合回测」→ 组合净值、成分贡献、相关性矩阵、换手率与平均暴露。真实 K 线对齐后按 T+1 开盘执行，含佣金/印花税/滑点。

④ 参数自动寻优

设标的、策略、K 段数、组合上限、排序依据（折外稳健分 / 样本内夏普 / 样本内收益），点「开始寻优」→ 网格搜索，按 0.6×各段收益中位 + 0.4×最差段 排序，结果可一键回写策略库参数。样本内绩效仅作参考。

所有回测都遵循 T+1、涨跌停不可成交、100 股整手、A 股真实费用（佣金/印花税/滑点）。回测收益不代表未来——详见第七章实测中的反面案例。

5.7 全链路工作流

① 单标的 10 步流水线

输入代码、选策略，点「▶ 启动全链路」。数据在「实时运行窗口」逐步推送：数据 → 统一口径 → 策略 → 稳健检验 → 回测 → 策略守护 → 风控 → 合规 → 多市场执行路由 → AI 复盘。右侧「流水线步骤与结果」显示每步状态与结果。

② 选股一条龙

选股策略、入选数量、组合再平衡、动量拉取上限，点「▶ 启动选股一条龙」。8 步：选股 → 组合回测 → 折外稳健 → 风控 → 合规 → 实盘意图(VALIDATED_ONLY) → AI 复盘。若已在上页选股，点「送入一条龙」可直接复用结果，不必重扫全市场。此流程只生成意图，绝不真实报单。

5.8 风控与合规

  • 执行模式：显示当前是 VALIDATE（只校验）还是 LIVE；默认 VALIDATE。
  • 合规规则：预交易闸（禁投池/限额/交易时段/审计留痕）。
  • 策略守护：健康 / 观察 / 退役三态监控，回撤或连败触发后需人工确认重启。
  • 合规审计日志：append-only 留存每笔决策的时间、标的、方向、数量、金额、决策、原因。

5.9 AI 助手

配好 AI 后在「AI 助手」页直接对话：可查询真实行情、运行回测、全市场选股、分析策略表现、查看风控合规状态。界面右上角标注当前是「云端 API」还是「本地降级」。AI 通过 function-calling 调用 7 大工具，所有数字来自真实工具结果，不做主观荐股、不承诺收益。

八、已知不足与能力边界

  1. 免费数据源非生产级 SLA：东财等公开接口可能临时限流/断连（本次就出现过，已加三源降级 + 缓存兜底）。研究和小资金够用；机构级、高频、五档深度需商业数据源。
  2. 不做 AI 荐股：AI 只做数据查询、回测编排、复盘分析，所有数字来自真实工具，不预测涨跌、不承诺收益。
  3. 港股实盘未接入：预留了接口，需券商 OpenAPI 凭证；CTP 期货、期权实盘需柜台参数配置，当前执行层默认只返回 VALIDATED_ONLY。
  4. QMT 实盘未在本机验证通过：scripts/verify_qmt_paper.py 默认 validate 自检；因本机无 xtquant/miniQMT/账户，结论诚实为未通过（见 reports/qmt_paper_verify.json）。真实报单需券商权限齐备并显式切换 live。
  5. 回测结果不代表未来：Dual Thrust 在 A 股日线实测为负、双均线稳健分极低——系统展示真实数据，不粉饰。任何策略都可能失效。
  6. 期权单合约历史短：受合约生命周期限制，长周期回测受限。
  7. 部分因子为推导值：新浪备源不提供财报同比，ROE 由真实 PB/PE 推导（约等于 ROE），结果页已明确标注，非财报披露值。
  8. 全市场扫描较慢：需历史数据的策略要拉真实 K 线，单次 30–90 秒属正常；可用「历史精算池」权衡速度与覆盖。
  9. 实盘需人工复核：策略守护退役、回撤熔断触发后需人工确认重启，不做无人值守全自动实盘。
  10. 历史报告口径问题：前视偏差修复前的旧报告收益数字（TSP 调研、波龙调研、多市场扩展方案中的收益）应以新引擎重跑后再采信。

九、注意事项与风险提示

  • 默认不真实下单：保持 paper/validate 模式；切 live 前务必完成券商权限开通、模拟账号充分验证、风控合规参数复核。实盘 QMT 通常需 10 万门槛 + C4 测评 + 6 个月经验 + Windows 常开登录独立交易模式。
  • 密钥只存本地：API Key/账户ID/Webhook 保存在 config/system.json，界面脱敏显示；不要把该文件随项目分享。环境变量优先级高于界面配置，注意别被覆盖。
  • 数据失败会明示：行情/选股失败会在界面显示错误或警告，不会用假数据填充；看到「加载失败」先检查网络与数据源状态，等待重试。
  • 参数决策看折外不看样本内：永远用 K 段折外稳健分选参数，样本内最高收益往往是过拟合陷阱。
  • 回测≠实盘：回测未考虑流动性冲击、部分成交、涨跌停排队等实盘摩擦，实盘结果通常更差。
  • 关闭窗口=停止服务：正在运行的任务会中断；长任务请等完成再关窗口。
  • 合规留痕别关：关闭审计留痕不符合合规要求，配置检查会提示。
