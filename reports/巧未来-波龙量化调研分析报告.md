## 执行摘要

「巧未来-波龙量化」是从零重建的 A 股量化系统，**不继续使用旧仓库中的随机数据与静默模拟报单**。系统当前状态：

- 数据：**全部真实**，东方财富主源 + 腾讯/新浪备源，脏数据直接拒绝。
- 研究：借鉴 TSP 的 enriched 单一口径、防未来函数引擎、K 段折外稳健分、策略守护、契约快照。
- 策略：13 个交易策略 + 10 个不同角度的全市场选股策略，全部基于公开理论自研实现。
- 回测：单标的回测、多策略并列对比、**多标的组合回测**、**参数自动寻优**。
- 工作流：单标的全链路 10 步；**选股 → 组合回测 → 风控 → 合规 → 实盘意图**一条龙 8 步。
- 执行：QMT/CTP/HK/Validate 多市场 Broker 抽象，默认校验模式，**连接失败抛错，绝不静默转模拟**。
- 合规：预交易闸 + 限额 + 交易时段 + append-only 审计日志。
- AI：OpenAI 兼容 API + 7 大工具调用；无 Key 自动降级为本地工具直答。
- 终端：9 个功能页，标准库 HTTP + REST + SSE 实时运行窗口，零第三方依赖。

**关键边界**：截至 2026-11-20，本机未安装 xtquant、无 miniQMT 进程、无券商模拟账号配置，**券商模拟账号报单验证尚未执行**。已产出可运行验证脚本与前置条件清单；报告中所有"实盘意图"均为 `VALIDATED_ONLY`，未产生任何真实委托。

## 二、真实数据源评估与选型

### 2.1 实测结论（2026-11-20 本机）

| 数据源 | 角色 | 实测能力 | 局限 |
|---|---|---|---|
| 东方财富 | 主源 | 全市场 5565~5931 只、日/周/月/分钟 K 线、前复权、PE/PB/ROE/营收/资金流快照 | clist 单页硬上限 100，必须分页；接口参数敏感 |
| 腾讯财经 | 实时快源 | 现价批量、延迟最低 | GBK 编码，需正确解码 |
| 新浪财经 | 备源 | 现价可用 | GBK 编码；稳定性略逊 |
| akshare / efinance | 不进主链 | 聚合封装 | 本质是爬虫，接口变动快，不宜做生产决策链 |

三源对贵州茅台现价交叉验证一致（不同时点分别得到 1432.54 与 1438.98 / 1438.98 / 1438.66），证明数据可信。

### 2.2 踩过的坑（已修复）

- 东财 clist 缺 `fltt=2&invt=2` 会失败；`pz=6000` 实际只返回 100。
- 东财价格字段 `f43` 放大 100 倍，需按字段口径还原。
- 腾讯/新浪返回 GBK，`decode('gbk','ignore')`。
- 东财分钟线 `beg=20500101` 返回空，统一使用 `beg=20200101`。
- F10 财务/估值专用接口返回反爬 HTML，改用快照估值字段 + 公司概况接口。
- Windows curl 中文请求体按 GBK 发送，服务端需 UTF-8 失败后降级 GBK 解码。

### 2.3 数据治理层

`core/data/resolver.py` 提供：
- 降级链：主源 → 备源 → 缓存（STALE 明确标注）
- 脏数据校验：价格越界、成交量为负、K 线 OHLC 关系异常直接拒绝
- 缓存策略：盘中 30 秒 / K 线 1 小时 / F10 1 天 / 全市场列表 1 天
- 交易时段门控：非交易时段减少空请求
- 配置热更新：TTL 从配置中心读取

## 四、研究层：从 TSP 借鉴的纪律

1. **enriched 单一口径**（`enriched-v1.0.0`）：基础数据少存，指标现算；任何策略、回测、实盘信号都经过同一 enrich。
2. **契约快照**：记录 contract version + 基础数据哈希，跨版本结果不一致可定位。
3. **防未来函数**：`signal_fn(bars[:i+1], i)` 物理截断未来；T 日收盘信号，T+1 开盘成交。
4. **A 股真实成本**：佣金万 2.5（最低 5 元）、印花税万 5（卖出）、过户费万 0.1、滑点、涨跌停不可成交、100 股整数倍。
5. **K 段折外稳健分**：`0.6 × 中位 + 0.4 × 最差段`，参数寻优以此排序。
6. **策略守护**：健康 / 观察 / 退役三态。
7. **因子归因**：卖出收益按买入时激活因子分摊。

详见 `reports/TSP_调研分析报告.md`。

## 七、选股一条龙工作流

新增 `core/workflow/selection_pipeline.py`，把选股结果直接接入全链路：

```
① 全市场选股（10 策略插件可选）
② 入选标的真实K线 + enrich 统一口径
③ 自动组合回测（选股权重 → 组合净值）
④ 组合层 K 段折外稳健性
⑤ 风控：策略守护 / 仓位 / 回撤熔断
⑥ 合规：禁投池 / 限额 / 时段 / 审计
⑦ 实盘意图：VALIDATED_ONLY 委托意图（不报单）
⑧ AI 复盘
```

关键设计：

- 目标权重先按单票/总仓位上限收缩，并留 0.5% 缓冲，避免"组合回测通过但风控末位标的超限"的自相矛盾。
- K 段折外先按共同交易日对齐，再切段，避免各标的历史长度不同导致错位。
- `live=True` 被硬性拒绝，本管线只生成意图。
- SSE 推送 8 步进度，前端同步观测。

### 实测（value 策略 / top 10 / 按月调仓）


## 八、执行层与 QMT 验证现状

### 8.1 已实现的执行能力

- `core/execution/base.py`：统一 `Order` / `Broker` / `Market` / `OrderStatus`。
- `core/execution/brokers.py`：
  - `QMTBroker`：迅投官方 `xtquant` SDK，本地 TCP 连 miniQMT
  - `CTPBroker`：期货 CTP 预留，未装库明确拒绝
  - `HKStockBroker`：港股预留，明确"未接入"，不伪造成交

- 严格边界：连接失败抛 `BrokerError`，绝不静默转模拟；只有显式 `live` 才报单。

### 8.2 券商模拟账号报单验证：尚未执行（诚实说明）

**本机检测结果**：

| 检查项 | 结果 |
|---|---|
| `xtquant` 是否安装 | ❌ `ModuleNotFoundError` |
| `config/system.json` 的 `qmt_path` | ❌ 空 |
| `account_id` | ❌ 空 |
| miniQMT 进程 | ❌ 未发现 |
| 交易时段 | ✅ 检测时处于时段内 |

因此**无法完成真实报单验证**，不会伪造成交记录。

**补齐前置条件后执行**：

```bash

# 2) 启动 miniQMT，登录券商模拟/仿真交易账号（独立交易模式）
```

## 十三、能力边界与风险

1. **免费数据源无 SLA**：接口可能变更或限流；系统有降级与明确报错，但不承诺生产级稳定性。
2. **不做 AI 荐股**：AI 只做工具调用与复盘，不给买卖建议。
3. **港股实盘未接入**：`HKStockBroker` 明确占位，不伪造成交。
4. **券商模拟账号报单未验证**：前置条件不具备，绝不伪造。
5. **回测不代表未来**：所有收益数字为历史真实数据计算，未来不保证。
6. **参数寻优仍可能过拟合**：折外稳健分显著抑制但不消除过拟合，需结合策略守护与人工判断。
7. **本地 Ollama 工具调用能力不一**：不支持 function-calling 的模型自动走本地直答路径。
