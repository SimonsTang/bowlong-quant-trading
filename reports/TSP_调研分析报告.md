# TSP（Tick Stock Panel）调研分析报告

> 调研对象：`shy3130/tick-stock-panel`（GitHub）
> 调研日期：2026-11-20
> 调研目的：判断 TSP 是否适合作为「巧未来-波龙量化」交易系统的升级参考
> 结论一句话：**研究层高度适配，交易执行层不适配，多市场/合规层不适配。**

---

## 一、执行摘要

TSP 是一个成熟的**自托管 A 股研究工作台**，不是交易执行系统。它的价值集中在"研究口径一致、防未来函数、参数不调样本内最优、策略生命周期管理"四件事上，这四件事恰好是量化团队最容易出错、也最容易被回测漂亮数字掩盖的地方。

对波龙而言：

| 维度 | 适配度 | 判断 |
|---|---|---|
| 研究/回测/因子/监控 | **8.5 / 10** | 直接借鉴机制，已在巧未来 v1.0~v1.4 实现 |
| 实盘交易执行 | **1 / 10** | 项目明确不做下单，必须自建 |
| 多市场多品种 | **2 / 10** | A 股为主，无统一 Broker 抽象 |
| 机构级合规 | **2 / 10** | 无预交易合规闸、无审计留痕、无限额体系 |
| 商用闭源集成 | **需法务评估** | MIT 历史版本，但贡献者协议指向未来 AGPL-3.0 + 商业双授权 |

**决策：借鉴机制、不复制代码、不依赖其运行环境。** 巧未来-波龙量化采用"研究层对标 TSP，执行/合规层自建"的路线。

## 三、值得借鉴的四大核心机制

### 3.1 Enriched 单一口径：少存基础、多现算

TSP 只持久化约 15 列基础行情，把约 68 列指标全部现算，策略扫描、回测、监控、复盘共享同一份 enriched 结果。

**解决的问题**：同一策略在回测里用 MA5 的一种算法、在监控里用另一种算法，导致"回测赚钱、实盘不对"。

**波龙实现**：`core/data/enriched.py`
- 基础列：`date/open/high/low/close/volume/amount`
- 现算列：MA5/10/20/60、EMA12/26、DIF/DEA/MACD 柱、RSI14、布林三轨、KDJ、ATR14、唐奇安通道、ret1/5/20、RPS20
- 契约版本：`enriched-v1.0.0`，口径变更必须升版

### 3.2 回测与实盘共用 StrategyEngine + "当日已知"约束

TSP 不让回测和实盘各写一套执行逻辑，而是共用同一个 `run`，信号只使用当前 bar 及以前的数据。

**解决的问题**：未来函数。典型错误是 T 日信号用 T 日收盘价成交，或用全样本计算的指标喂给历史 bar。

**波龙实现**：`core/research/engine.py`
- `signal_fn(bars[:i+1], i)`，物理上截断未来数据
- T 日收盘出信号，T+1 开盘成交
- `step_live()` 与 `run_on_bars()` 共用信号/成本语义

### 3.3 K 段折外稳健分：不选样本内最优

TSP 把时间序列切成 K 段，每段独立做样本外检验，并定义：

```
稳健分 = 0.6 × 各段收益中位数 + 0.4 × 最差段收益
```

**解决的问题**：一组参数在某一段爆赚、其余段亏死，样本内总收益仍然很好看。0.4 的最差段惩罚把这种过拟合参数压下去。

**波龙实现**：`core/research/robustness.py`，并进一步用于 `core/research/optimizer.py` 的参数寻优排序——样本内收益只作参考，不决定冠军。

### 3.4 策略守护与契约快照

- 策略守护：健康 / 观察 / 退役三态，回撤或连败触发状态迁移，避免"策略坏了还在跑"。
- 契约快照：记录 contract version + 基础数据哈希，跨版本结果不一致时可定位。

**波龙实现**：`core/research/guard.py`、`core/data/enriched.py::contract_snapshot()`。

## 四、明确的能力边界（ TSP 不做的事）

| 边界 | 说明 | 对波龙的影响 |
|---|---|---|
| 不做实盘下单 | 项目定位就是研究工作台 | 必须自建 QMT/CTP 执行层 |
| 不做 AI 荐股 | AI 助手用于研究提效，不给买卖建议 | 波龙 AI 也定位为工具调用与复盘，不做荐股 |
| 不对标同花顺/通达信 | 不是行情终端替代品 | 波龙 Web 终端需自己补齐专业 UI |
| A 股为主 | 无多市场统一抽象 | 波龙自建 `Market.CN_A/CN_FUTURES/HK` + Broker 路由 |
| 依赖第三方数据源 Key | TickFlow/fuyao/TdxQuant | 波龙采用东财/腾讯/新浪免费真实源 + 降级链 |

## 五、工程与质量风险（必须写清）

1. **第三方沙箱测试质量差**：mrkeyoor 沙箱（2026-08-23，commit `38186e2`）测试结果为 77 通过 / 21 失败 / 105 错误。不能把"测试套件存在"等同于"质量可靠"。
2. **公开的静默数据错误 issue**：
   - #539：覆盖整个市场数据
   - #538：volume 放大 100 倍
   - #552：行数翻倍
   - #571：跨版本结果不一致
   这类问题对量化是致命的——回测数字可能建立在错误数据上。
3. **Windows 原生崩溃**：#542 / #546；桌面端与内存问题 #551。
4. **迭代速度快导致口径漂移**：单人主导、版本高频，研究结论跨版本复现成本高。
5. **资源占用**：常驻约 1.3GB（243 日 / 108 万行），回测 worker 另约 800MB。唐老师机器 16GB 内存，不构成约束；2GB 小主机需限线程。
6. **AI 工具调用依赖模型能力**：OpenAI 兼容 function-calling 是前提；本地 Ollama 部分模型不支持工具调用，会退化为纯文本。波龙因此做了"无 Key / 无工具能力自动降级为本地工具直答"。

## 六、许可与商用风险

- 主线仓库当前为 **MIT**，历史贡献可商用。
- `CONTRIBUTING` 第 14 节要求贡献者授予维护者**永久再许可权**，并明示未来拟切换 **AGPL-3.0 + 商业双授权**。
- 判断：
  - 个人研究/内部使用：风险低。
  - 商业闭源产品集成分发：需在切换授权前完成法务评估，或直接采用"机制借鉴 + 自研实现"路线。

**波龙采取的路线**：机制借鉴、自研代码，不复制 TSP 源码，不引入其 AGPL 风险。

## 八、结论与建议

1. **值得继续借鉴**：研究层的口径纪律、稳健分、策略生命周期三件事已经转化为波龙代码，建议后续新增任何策略都必须经过 enriched + 折外检验才能进入策略库。
2. **不要直接 fork TSP 当交易系统**：它明确不做实盘，强行改造的成本高于自建。
3. **不要复制其数据层代码**：公开 issue 显示存在静默数据错误；波龙宁可自己写降级链 + 脏数据校验。
4. **商用前做许可复核**：若未来考虑集成 TSP 代码而非机制，需在 AGPL 切换前完成法务确认。
5. **对本地 Ollama 环境的提醒**：若要接 TSP 式 AI 助手，优先选支持 tool calling 的模型；否则使用波龙的本地工具直答降级路径。
